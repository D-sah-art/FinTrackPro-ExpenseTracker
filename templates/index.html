FinTrack Pro — Semester Project Architecture & Viva Guide

Technical specification for college laboratory evaluation, internal assessments, and end-semester project viva.

1. Full-Stack Dual Architecture

  • REST API Backend: Python 3 + Flask (`app.py`) providing CRUD endpoints for transactions, categories, budgets, and user profiles.
  • Database Layer: SQLite3 with B-Tree indices on `(user_id, tx_date)` and `(user_id, category)` for O(log N) fast lookups.
  • Dual-Mode Client: Automatically binds to the Flask SQLite REST API when accessed over HTTP, with transparent fallback to browser `localStorage` in static zero-install mode.
  • Analytics Engine: Real-time category percentage aggregations and Chart.js 4.4 interactive canvas visualization.

2. Relational Database Schema (3NF)

  • users: Primary entity storing id (PK), username (UNIQUE), password_hash, created_at.
  • categories: User-scoped streams id (PK), user_id (FK), name, cat_type, color, icon with composite unique constraint.
  • budgets: Monthly limits id (PK), user_id (FK), category, monthly_limit with cascading delete.
  • transactions: Itemized ledger id (PK), user_id (FK), title, amount, tx_type, category, payment_method, tx_date, notes.

Top Viva Voce Questions & Model Answers

Q1: How does FinTrack Pro ensure data consistency and multi-user isolation?

Every transaction, category, and budget row is strictly indexed by foreign key user_id REFERENCES users(id) ON DELETE CASCADE. All REST API endpoints parameterize queries with SQLite prepared statements preventing SQL injection and isolating multi-student ledgers.

Q2: How are budget warning thresholds calculated?

Budget utilization is computed dynamically as (SUM(expense_amount) / monthly_limit) * 100 per category for the selected billing month. Threshold triggers display amber warnings at ≥80% and red alert banners at ≥100%.

Q3: How does the application handle offline vs online server states?

On load, the frontend issues an asynchronous probe to /api/status. If the Flask server responds, it synchronizes via REST API. If the connection fails or if opened as a local file:/// URL, it falls back seamlessly to browser localStorage with zero disruption.
